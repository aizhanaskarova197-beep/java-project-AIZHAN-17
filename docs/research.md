# Research: Dodo Pizza Kazakhstan

## 1. Ұйым туралы

**Dodo Pizza** — 2011 жылы Сыктывкарда құрылған халықаралық пиццерия желісі. Қазақстанда 2015 жылдан жұмыс істейді, 2025 жылы елде 100-ден астам пиццерия болды. Тапсырыс өз бұлттық жүйесі **Dodo IS** арқылы өңделеді: тапсырыс асхана планшетіне түсіп, кезеңдерден өтеді (жайма, толтырма, пеш, орау), содан кейін жеткізіледі немесе пиццерияда беріледі.

## 2. Анықталған проблема

**Клиентке тапсырған пиццасының орнына басқа пицца беріледі.** Мысалы, клиент «Пепперони» тапсырады, бірақ орау немесе беру кезінде қателік болып, оған «Гавай» пиццасы беріледі. Бірнеше пицца қолмен оралады, ал тапсырыс құрамымен салыстыру болмаса, қате клиентке дейін жетеді. Нәтижесінде клиент наразы болады, тапсырысты қайта жасауға немесе ақшаны қайтаруға тура келеді.

Дәлел: Dodo пиццерияларына қалдырылған пікірлерде осындай шағымдар кездеседі (пиццаны ауыстырып жіберген): https://www.restoclub.ru/msk/place/dodo-picca/opinions. Бұл пікірлер Ресейдегі пиццерияларға қатысты, желіге тән типтік шағым ретінде алынды.

## 3. Ұсынылатын шешім

Қаптаманы тапсырыспен салыстыратын тексеруі бар Java консольдік жүйесі:

- тапсырыс құрамы нақты сақталады (пицца атауы және өлшемі);
- чекте құрам толық көрсетіледі, оператор клиентпен тексереді;
- аспаз қаптамаға нені салса, соны енгізеді, жүйе оны тапсырыс құрамымен салыстырады;
- сәйкес келмесе, қате шығады: «тапсырыста Пепперони, ал қаптамада Гавай» (`WrongItemException`), пакетті қайта жинау керек;
- тексеруден өтпеген тапсырыс курьерге де, клиентке де берілмейді;
- статус тек ретімен өзгереді: NEW → COOKING → READY → DELIVERING → DONE.

## 4. Жобаның мақсаты

Dodo Pizza Kazakhstan тапсырыстарында клиентке басқа пицца берілуін болдырмайтын жеңілдетілген жүйені Java тілінде әзірлеу.

## 5. Жобаның міндеттері

1. Ұйымды зерттеп, проблеманы анықтау.
2. UML диаграммаларын салу (Use Case, Class, Sequence, Activity).
3. Мәзірді CSV файлынан жүктеу, тапсырыс жасау және чек шығару.
4. Асхана кезегін, статустарды және курьерді автоматты тағайындауды жасау.
5. Қаптаманы тапсырыспен салыстыратын тексеруді жасау, сәйкессіздікте өз ерекше жағдайын (`WrongItemException`) лақтыру.
6. Тапсырыстарды файлға сақтау, JUnit тесттерін жазу, жобаны GitHub-қа жүктеу.

## 6. Қолданылатын техникалар мен технологиялар

Java 17, Maven, JUnit 5, Git/GitHub, draw.io, CSV файлдар. ООП (абстракция, мұрагерлік, полиморфизм, инкапсуляция), интерфейс, абстракт класс, коллекциялар (`ArrayList`, `HashMap`, `Queue`), exception.

## 7. Күтілетін нәтиже

Жұмыс істейтін Java қосымшасы мен UML диаграммалары. Демода көрсетіледі:
1. Пепперони орнына Гавай қапталса, жүйе қатені көрсетеді.
2. Тексерілмеген тапсырыс курьерге де, клиентке де берілмейді.
3. Қаптама дұрыс жиналса, тапсырыс беріледі.
