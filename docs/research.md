# Research: Dodo Pizza Kazakhstan

> Учебный проект. Использованы только открытые источники (сайт, новости, публикации компании). Внутренние данные организации не запрашивались. Система в проекте намеренно упрощена.

## 1. Краткое описание организации

**Dodo Pizza («Додо Пицца»)** — международная сеть пиццерий, работающая в основном по франчайзинговой модели. Сеть основана в 2011 году в Сыктывкаре (Россия) предпринимателем Фёдором Овчинниковым. Компания позиционирует себя как «IT-компания, которая делает пиццу»: вся работа пиццерий построена вокруг собственной облачной информационной системы **Dodo IS**.

**Dodo Pizza в Казахстане**
- В Казахстане сеть работает с 2015 года (пиццерия в Костанае), в Алматы пиццерия открылась в конце 2016 года.
- По состоянию на июнь 2025 года в Казахстане работает более 100 пиццерий «Додо Пицца» и 14 кофеен «Дринкит» (кофейная сеть того же холдинга).
- Материнский холдинг Dodo Brands в 2025 году перерегистрировался из Британских Виргинских островов в Международный финансовый центр «Астана» (МФЦА).
- Основные каналы продаж: заказ в пиццерии, самовывоз, доставка курьером; заказ оформляется через сайт и мобильное приложение.
- Меню: пиццы разных размеров, закуски, напитки, десерты, комбо и акции.

**Dodo IS** — собственная система компании, которая автоматизирует работу пиццерий: приём и отслеживание заказов, управление меню и ценами, учёт сырья, графики смен, аналитику продаж. По данным самой компании, пиковая нагрузка системы в 2025 году достигла 1 040 заказов в минуту.

## 2. Выбранный бизнес-процесс

**Приём и выполнение заказа в пиццерии**: от оформления заказа клиентом до выдачи/доставки и расчёта.

Упрощённый поток:

1. Клиент (или оператор) просматривает меню.
2. Формируется заказ: добавляются пиццы (с выбором размера) и напитки.
3. Система проверяет, что заказ не пустой, и считает счёт (Bill).
4. Заказ попадает в очередь кухни (Kitchen).
5. Пиццемейкер берёт заказ из очереди, статус меняется на «Готовится», затем «Готов».
6. Для доставки заказ назначается курьеру (Courier), статус «В пути», затем «Выдан».
7. Заказ и счёт сохраняются в файл.

Почему этот процесс: он покрывает все классы варианта 17 (`MenuItem`, `Pizza`, `Drink`, `Order`, `Kitchen`, `Courier`, `Bill`), легко ложится на консольное приложение и хорошо показывает ООП (наследование, полиморфизм, коллекции).

## 3. Акторы

| Актор | Роль в системе |
|---|---|
| **Клиент** | Просматривает меню, создаёт заказ, оплачивает, получает заказ |
| **Оператор / кассир** | Принимает заказ от клиента в пиццерии или по телефону, оформляет и закрывает счёт |
| **Пиццемейкер (повар)** | Берёт заказы из очереди кухни, готовит, отмечает готовность |
| **Курьер** | Получает готовый заказ, доставляет клиенту, отмечает выдачу |
| **Менеджер пиццерии** | Управляет меню (добавление/изменение позиций), просматривает историю заказов |

## 4. Функциональные требования

| № | Требование |
|---|---|
| FR-1 | Система показывает меню: пиццы и напитки с названием, ценой и описанием |
| FR-2 | Система загружает меню из файла `data/menu.csv` при запуске |
| FR-3 | Пользователь может создать новый заказ |
| FR-4 | Пользователь может добавлять в заказ и удалять из него позиции меню |
| FR-5 | Для пиццы можно выбрать размер (25, 30, 35 см), цена зависит от размера |
| FR-6 | Система не принимает пустой заказ и выбрасывает собственное исключение `EmptyOrderException` |
| FR-7 | Система рассчитывает итоговую сумму заказа и формирует счёт (Bill) |
| FR-8 | Принятый заказ ставится в очередь кухни (порядок FIFO) |
| FR-9 | Повар берёт следующий заказ из очереди, статус меняется NEW → COOKING → READY |
| FR-10 | Готовый заказ назначается свободному курьеру, статус READY → DELIVERING → DONE |
| FR-11 | Менеджер может добавить новую позицию в меню |
| FR-12 | Заказы и счета сохраняются в файл (`data/orders.csv` или JSON) и доступны после перезапуска |

**Нефункциональные требования:** консольный интерфейс, Java 17+, понятные сообщения об ошибках, данные хранятся в файлах (без БД), код покрыт частично JUnit-тестами.

## 5. Сравнение с аналогичными системами
| Критерий | Dodo Pizza | Papa John's | Наша система |
|---|---|---|---|
| Происхождение | Россия, 2011 | США, 1984 | Учебный проект |
| Каналы заказа | Приложение, сайт, колл-центр, касса, киоск | Приложение: доставка или самовывоз | Консольное меню |
| Состав заказа | Две половинки, свои ингредиенты | Свой рецепт, правка ингредиентов | Пицца с размером и напитки |
| Оплата | Нет данных в открытых источниках | Карта, наличные, сохранённая карта | Расчёт счёта (Bill) |
| Статус для клиента | Прямой эфир кухни, курьер на карте | Статус заказа в реальном времени | NEW, COOKING, READY, DELIVERING, DONE |
| Кухня | Заказ сразу на планшет | Заказ уходит в пиццерию, видны статусы | Очередь Queue (FIFO) |
| Приложение курьера | Заказ в приложении, маршрут, GPS | Отметка взятых заказов, статус, карта, статистика | Класс Courier |
| Назначение курьера | Очередь курьеров, следующий заказ по очереди | Курьер сам берёт заказы | Автоматически первому свободному |
| Лояльность | Додокоины, скидки | Баллы кэшбэком, акции | Нет |
| Система | Собственная Dodo IS | Не раскрывается | Java, файлы CSV |
| Хранение данных | Облачные БД | Облачные БД | CSV/JSON файлы |

**Вывод:** учебная система реализует только ядро процесса «меню → заказ → кухня → курьер → счёт». Остальные функции Dodo IS (учёт сырья, смены, аналитика, интеграции) сознательно исключены.


## 6. Соответствие классам проекта

| Сущность | Класс / тип в коде |
|---|---|
| Позиция меню | `MenuItem` (abstract) |
| Пицца, напиток | `Pizza`, `Drink` (наследуют `MenuItem`) |
| Заказ | `Order` |
| Кухня и очередь | `Kitchen` |
| Курьер | `Courier` |
| Счёт | `Bill` |

Это даёт 10 типов, что покрывает требование «минимум 8 классов, 1 интерфейс, 1 абстрактный класс, своё исключение».

## 7. Требования к реализации (что нужно для кода)

Этот раздел переводит результаты исследования в конкретные решения для Java-проекта. Цены и коэффициенты учебные, они не взяты из внутренних данных Dodo.

### 7.1 Данные и файлы

**`data/menu.csv`** — меню, загружается при старте:

```
type,name,basePrice,extra
PIZZA,Пепперони,3500,
PIZZA,Маргарита,3000,
PIZZA,Четыре сыра,3900,
DRINK,Кола,700,0.5
DRINK,Сок яблочный,800,0.3
```

- `type` определяет, какой объект создавать (`Pizza` или `Drink`).
- `basePrice` — цена в тенге (для пиццы это цена размера 25 см).
- `extra` — объём напитка в литрах (для пиццы пусто).

**`data/orders.csv`** — сохранённые заказы:

```
orderId,status,delivery,courier,items,total
1,DONE,true,Ерлан,Пепперони(30);Кола,5250
```

### 7.2 Бизнес-правила

| Правило | Решение |
|---|---|
| Размеры пиццы | 25 / 30 / 35 см, коэффициент цены 1.0 / 1.3 / 1.6 |
| Итоговая сумма | сумма цен всех позиций заказа (`Bill` считает через `Payable`) |
| Пустой заказ | отправить на кухню нельзя, выбрасывается `EmptyOrderException` |
| Номер заказа | автоинкремент, начиная с 1 |
| Очередь кухни | FIFO: первый принятый заказ готовится первым |
| Статусы | NEW → COOKING → READY → DELIVERING → DONE (самовывоз: READY → DONE) |
| Курьер | назначается только заказу с доставкой, только свободный |
| Менеджер | может добавить позицию в меню, она записывается в `menu.csv` |

### 7.3 Структуры данных (коллекции)

| Где | Коллекция | Зачем |
|---|---|---|
| Меню | `Map<Integer, MenuItem>` (HashMap) | быстрый поиск позиции по номеру |
| Позиции заказа | `List<MenuItem>` (ArrayList) | порядок добавления, дубликаты разрешены |
| Очередь кухни | `Queue<Order>` (LinkedList) | FIFO: `offer()` и `poll()` |
| Курьеры | `List<Courier>` (ArrayList) | поиск свободного курьера |
| История заказов | `List<Order>` (ArrayList) | запись в файл, просмотр |

### 7.4 Четыре принципа ООП в проекте

- **Абстракция:** абстрактный класс `MenuItem` с абстрактным методом `getDescription()`.
- **Наследование:** `Pizza` и `Drink` наследуют `MenuItem`.
- **Полиморфизм:** `Order` хранит `List<MenuItem>` и вызывает `getDescription()` и `getPrice()`, не зная, пицца это или напиток; `Pizza` считает цену с учётом размера.
- **Инкапсуляция:** поля `private`, доступ через геттеры; статус заказа меняется только методами `Order`.

### 7.5 Интерфейс и исключения

- Интерфейс `Payable` с методом `double calculateTotal()`; его реализуют `Order` и `Bill`.
- `EmptyOrderException extends Exception` (проверяемое исключение).
- Дополнительно обрабатываются `IOException` при чтении/записи файлов и неверный ввод пользователя в консоли.

### 7.6 Консольное меню (сценарии использования)

```
1. Показать меню
2. Создать заказ
3. Добавить позицию в заказ
4. Оформить заказ (счёт + отправка на кухню)
5. Кухня: приготовить следующий заказ
6. Назначить курьера и доставить
7. История заказов
8. Добавить позицию в меню (менеджер)
0. Выход (сохранение в файл)
```

Каждый пункт соответствует прецеденту из Use Case диаграммы и требованиям FR-1 … FR-12.

### 7.7 Что выходит за рамки

Онлайн-оплата, реальные адреса и карты, учёт сырья, графики смен, база данных, графический интерфейс.
